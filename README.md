# VISANG QA AI

웹 서비스의 두 환경(예: 운영 ↔ STG, 개발1 ↔ 개발2)을 자동으로 탐색·캡처·비교하는 로컬 QA 도구입니다. 화면 차이와 HTTP·JS 오류를 스크린샷 근거와 함께 기록하고, 결과를 **이슈 / 대인체크 / 재검 / 정상**으로 분류해 보여 줍니다.

- **환경 비교 QA** — 같은 페이지를 A·B에서 캡처해 화면 차이율을 계산 (`/`, `/#/`, `/main`, `.do`처럼 URL 모양만 다른 페이지도 같은 페이지로 매칭)
- **단일 환경 QA** — HTTP·JS 오류, 깨진 이미지, 필수 영역 확인
- **회귀 테스트** — 과거 실행과 비교해 신규·재발·해결 후보 분류
- **조건 기반 UI QA** — 검사 규칙(요소 표시·개수·텍스트 길이·넘침)을 화면에서 확인, 엑셀 테스트 케이스 가져오기
- 테스트 계정 자동 로그인, 커버 페이지 통과, 팝업 자동 닫기, 같은 모양 게시글 샘플링
- 라이트 / 다크 / 시스템 테마

Python 3.10+ · Playwright(Chromium) · Pillow · 바닐라 HTML/CSS/JS

## 설치와 실행 (Windows)

1. `setup_windows.bat` 실행 — 가상환경, 패키지, Chromium 설치 (처음 한 번, 패키지가 바뀌면 다시)
2. `run_windows.bat` 실행
3. 브라우저에서 **http://127.0.0.1:3000** 열기

직접 실행:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe app.py
```

포트는 `PORT`, 결과 폴더는 `QA_RUNS_DIR` 환경변수로 바꿀 수 있습니다. 서버는 이 PC(127.0.0.1)에서만 열립니다.

## 사용 순서

1. **설치** — `setup_windows.bat` 실행 (처음 한 번)
2. **서버 켜기** — `run_windows.bat` 실행 → 브라우저에서 http://127.0.0.1:3000
3. **(처음이면) 데모로 연습** — **검사 실행** 화면에서 프로필 `합성 데모` 선택 → 담당자 입력 → **검사 시작**
4. **프로젝트 등록** — 사이드바 **프로젝트 설정** → `+ 새 프로젝트` → 환경 A(기준)·B(비교)의 이름과 URL 입력 → 저장 → **검사 설정에 적용 →**
5. **테스트 계정 저장** (로그인 검사를 할 때만) — 검사 설정 4단계에서 ID·비밀번호 입력 → **계정 저장**. 환경마다 계정이 다르면 4번에서 환경별 로그인 정보로 입력
6. **검사 설정** — 테스트 목적 선택 → 인증 상태(비로그인 / 로그인 / 수동 로그인) 선택 → A/B 주소 확인 → 담당자 입력. 전체를 훑으려면 **⚡ 전체 기능 자동 체크 프리셋** 클릭
7. **검사 시작** — 진행 상황이 표시됩니다. 수동 로그인이면 열린 브라우저 창에서 로그인한 뒤 **로그인 완료 · 계속**. 진행 단계는 **실행 결과** 화면에서도 실시간으로 볼 수 있습니다
8. **결과 확인** — **실행 결과**에서 검사를 고르고 **전체 결과·검수 보기 →**. 상단 타일에서 **이슈 → 대인체크 → 재검** 순으로 보고, 각 행을 펼쳐 A·B·차이 스크린샷과 판정 근거 확인
9. **검수 기록** — 행마다 검수 결과와 사유를 저장 (필요하면 이슈 URL 첨부)
10. **내보내기·정리** — **CSV 저장**으로 내려받기, 필요 없는 실행 기록은 실행 이력에서 삭제. 최근 실행 요약은 **대시보드**에서 확인

## 화면별 안내

### 1. 처음이라면: 합성 데모

**검사 실행** 화면에서 프로필 **합성 데모**를 고르고 담당자를 입력한 뒤 검사 시작. 외부 접속 없이 앱 안의 A/B 데모 사이트로 전체 흐름을 볼 수 있습니다. 데모에는 일부러 넣은 결함이 있어서 모든 행이 PASS가 아닌 것이 정상입니다.

### 2. 프로젝트 설정

사이드바 **프로젝트 설정**에서 프로젝트와 환경(이름·URL)을 등록합니다. 첫 환경이 A, 둘째가 B가 됩니다. 환경마다 로그인 URL·ID·비밀번호를 선택으로 넣을 수 있습니다.

- 기본 저장 위치: `local-settings/projects.json` (git 제외)
- PostgreSQL을 쓰려면 프로젝트 루트 `.env`에 `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`를 넣으세요. 스키마는 [docs/db](docs/db/m_local_db_schema.md)에 있습니다.
- 비밀번호는 암호화해 저장하고 화면·보고서에 다시 나오지 않습니다. 첫 저장 때 `.env`에 `QA_CREDENTIAL_KEY`가 생기며, 이 키를 지우면 저장된 비밀번호를 다시 입력해야 합니다.

### 3. 검사 실행

1. 프로젝트(또는 제품 프로필)와 테스트 목적 선택
2. **인증 상태** 선택
   - **비로그인** — 로그인하지 않고 검사. 로그인 화면으로 이동되면 그 페이지는 미실행(SKIP)으로 남기고 계속 탐색
   - **로그인** — 테스트 계정으로 자동 로그인 후 검사. 세션이 끊기면 한 번 다시 로그인
   - **수동 로그인** — 열린 브라우저 창에서 직접 로그인한 뒤 계속 (SSO·OTP용)
3. A/B 환경 확인 → 검사 시작

**⚡ 전체 기능 자동 체크 프리셋**을 누르면 자동 로그인, 넓은 탐색 범위(60페이지·깊이 4), 버튼 스모크 클릭, 사소한 화면 차이(8% 미만) PASS, 콘솔 오류 "기타" 분리를 한 번에 켭니다.

### 4. 테스트 계정

로그인 검사는 아래 순서로 계정을 찾습니다.

1. 환경변수 `QA_LOGIN_A_ID` / `QA_LOGIN_A_PW` (B는 `QA_LOGIN_B_*`)
2. 프로젝트 설정에 등록한 환경별 로그인 정보
3. 공용 테스트 계정 — 검사 설정 4단계에서 **계정 저장**, 또는 `setup_login_windows.bat` (`secrets/accounts.json`, git 제외)

계정이 없으면 검사를 시작하기 전에 알려 줍니다. 회원탈퇴·비밀번호 변경·로그아웃·결제·회원가입은 어떤 설정에서도 누르지 않습니다. 자세한 내용은 [로그인·비밀 관리](docs/LOGIN_AND_SECRETS.md)를 보세요.

### 5. 검사 규칙

사이드바 **검사 규칙**에서 프로젝트별 조건(예: 빈 목록 안내가 보여야 함, 제목이 넘치지 않아야 함)을 만들고 **활성 규칙을 검사 설정에 적용**을 누르면 조건 기반 UI QA로 실행됩니다.

엑셀(.xlsx) QA 목록을 드래그하거나 선택하면 테스트 케이스를 한 번에 등록합니다. `TC ID`, `제목`, `확인내용`, `테스트 단계`, `판정기준` 열을 읽고, `요소 선택자`·`검사 종류`·`기대값`까지 있는 행만 자동 실행 가능으로 등록합니다. 나머지는 "매핑 필요"로 남겨 목록에서 열어 수정할 수 있습니다. 같은 파일·시트·행을 다시 올려도 중복 등록하지 않습니다. 규칙은 프로젝트와 같은 저장소(`local-settings/rules.json` 또는 PostgreSQL)에 저장됩니다.

### 6. 실행 결과

사이드바 **실행 결과**에서 검사 목록(전체 / 검사 중 / 종료)과 선택한 검사의 진행 단계, 결과 요약, 항목별 검증식·스크린샷을 봅니다. 진행 중인 검사는 몇 초마다 자동으로 갱신됩니다. 검수 저장과 CSV 내려받기는 **전체 결과·검수 보기 →**에서 합니다.

## 결과 보기

| 상태 | 의미 |
|---|---|
| PASS | 기대값 충족 |
| FAIL | 기대 계약 위반 |
| DIFF | 차이 확인, 버그 여부 미확정 |
| REVIEW | 판단 근거 부족 |
| SKIP | 설정·정책상 제외 |
| BLOCKED | 로그인·데이터·한도 때문에 수행 못 함 |
| ERROR | 도구 오류 |

상단 타일은 이 상태를 **이슈(기능 문제) / 대인체크(데이터·이미지 차이 등 사람이 볼 것) / 재검(로그인·한도) / 정상 / 미실행**으로 묶어 보여 줍니다. 각 행에서 A·B·차이 스크린샷과 판정 근거를 확인하고 검수 결과를 저장할 수 있습니다. CSV/JSON 내려받기와 실행 기록 삭제도 지원합니다.

결과는 `runs/<실행 ID>/`에 저장됩니다(git 제외). 실제 서비스 스크린샷을 외부에 공유하기 전에는 개인정보가 없는지 확인하세요.

**화면 비교가 이상할 때**
- 한쪽만 로딩 중이거나 비어 있으면: 결과의 차단 목록에서 호스트를 확인해 `resourceHosts`에 추가
- 한쪽에만 팝업이 있으면: 팝업 자동 닫기가 켜져 있는지 확인, 안 닫히면 닫기 버튼 선택자를 3단계에 입력
- 공지·게시판이 끝까지 열리면: **같은 모양 페이지 샘플 수**(기본 3)를 조정

## 테스트

```powershell
.\.venv\Scripts\python.exe -B scripts/run_tests.py
```

로컬 합성 데이터만 사용하며 Chromium이 설치되어 있어야 합니다.

## 폴더 구조

```text
app.py            로컬 서버 · API
qa/               검사 엔진 (탐색·캡처·비교·판정·로그인·저장)
public/           웹 화면 (대시보드 · 프로젝트 설정 · 검사 규칙 · 검사 실행 · 실행 결과)
tests/            테스트
docs/             상세 문서
secrets/          테스트 계정 예시 (실제 계정 파일은 git 제외)
```
