# VISANG QA AI

> 비상교육 웹 서비스(초등·중고등 PC/모바일, 운영·STG·개발 4환경)를 위한 **증거 기반 웹 QA 워크스페이스**.
> 두 환경을 자동 탐색·캡처·비교하고, 모든 판정에 스크린샷·HTTP·JS 관찰 근거를 붙이며, 결과를 **이슈 / 대인체크 / 재검 / 정상**으로 분류해 QA 담당자가 바로 행동할 수 있게 합니다. (내부 코드명: Web QA Comparator · v0.5.0 · 규칙 v2.3)

## 핵심 설계 세 가지

**1. 동등 라우트 매칭 — "홈인데 `/`와 `/#/`라서 안 맞던 것"** · `qa/matching.py:equivalent_route_key`
`#/` 접두어, `.do/.html/.jsp` 확장자, 끝 슬래시, 홈 별칭(`/`, `/main`, `/index`)만 접어 같은 라우트 키를 만든다. 제목이 같거나 `#/` 접두어만 다르면 확정(`EQUIVALENT_ROUTE`), 아니면 후보로만 제안한다. 쿼리 순서·상세 ID(`?id=1` vs `?id=2`)는 절대 접지 않는다. 설정에서 끌 수 있고 명시적 별칭이 항상 우선한다.

**2. 검수 분류(Triage) — "DB 차이는 대인체크, 기능 미작동은 이슈, 404 떠도 동작하면 대인체크"** · `qa/triage.py` · [결정표](docs/TRIAGE_POLICY.md)
자동 판정은 그대로 두고, 검증식 사유 코드와 발견 분류로 다섯 분류를 만든다. 결과 대시보드 상단 타일·행 배지·CSV 열·검수 폼 기본값으로 쓰이며, 최종 결정은 검수자가 사유와 함께 저장한다.

**3. 테스트 계정 로그인 — "로그인은 되어야 하고 계정은 새지 말아야" (선택자 없으면 자동 탐지)** · `qa/secrets.py` · [안내](docs/LOGIN_AND_SECRETS.md)
API에는 로그인 폼 **선택자만** 보낸다(`password` 류 키는 거부). 계정·비밀번호는 엔진이 로그인 직전에 환경변수(`QA_LOGIN_A_ID/PW`) 또는 git-ignored `secrets/accounts.json`에서 읽고, 보고서·CSV·캡처·로그 어디에도 남기지 않는다(테스트로 보장). 성공 근거(`successSelector`)가 없으면 PASS를 주지 않는다. SSO/OTP는 기존 수동 로그인을 쓴다.

실사이트에는 승인한 경로·요소·기대값 설정이 필요합니다. 검색·입력·history 기능 시나리오는 공개 가능한 합성 데모에 등록되어 있고, 조건 계약은 사용자가 지정한 실사이트의 DOM에도 적용할 수 있습니다. 현재 지원 범위와 검증 결과는 [구현 현황](docs/IMPLEMENTATION_STATUS.md), 운영 절차는 [운영 안내](docs/OPERATIONS.md), 개발자 계약은 [결과 계약](docs/RESULT_CONTRACT.md), 화면 규칙은 [UI 가이드](docs/UI_GUIDE.md), 소개·발표용 구조 설명은 [구조 개요](docs/ARCHITECTURE_OVERVIEW.md)를 보세요.

## 인증 상태 — 로그인 / 비로그인 검사

검사 설정 1단계에서 **인증 상태**를 고릅니다(API `authMode`). 같은 모드가 A/B에 적용되고, 로그인 성공 여부는 환경별로 따로 기록됩니다.

- **비로그인** — 계정을 읽지 않고 로그인 링크·버튼을 누르지 않습니다. 탐색 중 로그인 화면으로 이동되면 그 화면을 캡처 증거와 함께 `LOGIN_REQUIRED_ANONYMOUS`(SKIP·미실행)로 남기고, 링크가 있던 직전 페이지 기준으로 탐색을 계속합니다. 로그인이 필요한 기능은 PASS로 집계되지 않습니다.
- **로그인** — 시작 전에 자동 로그인합니다. 계정이 없는 환경이 있으면 **시작 전에** 알려 줍니다. 탐색 중 세션이 끊겨 로그인 화면으로 튕기면 1회 다시 로그인하고 원래 페이지로 돌아가며(`RELOGIN_OK`), 그래도 안 되면 `LOGIN_SESSION_LOST`(BLOCKED·재검)입니다.
- **수동 로그인** — 열린 브라우저에서 사람이 로그인한 뒤 계속합니다(SSO·OTP).

계정은 `QA_LOGIN_A/B_*` 환경변수 → **프로젝트 설정의 환경별 로그인 정보** → 공용 테스트 계정 순으로 씁니다. 보고서 `manifest.auth`에 모드·로그인 여부·이동 기록이 남고 비밀번호·쿠키는 남지 않습니다. → [로그인·비밀 관리](docs/LOGIN_AND_SECRETS.md)

## 프로젝트 설정 저장소

프로젝트·환경 목록과 환경별 로그인 정보(선택)는 서버가 저장합니다. 기본은 설정이 필요 없는 **`local-settings/projects.json`**(git 제외)이고, 프로젝트 루트 `.env`에 `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`를 넣으면 **로컬 PostgreSQL**을 씁니다(테이블은 처음 접근할 때 생성, 스키마 [m_local_db_schema](docs/db/m_local_db_schema.md), 공유용 시드 [m_project_seed](docs/db/m_project_seed.md)). 비밀번호는 Fernet 암호문으로만 저장되며 첫 저장 때 `.env`에 `QA_CREDENTIAL_KEY`가 생깁니다 — 이 키를 잃으면 저장된 비밀번호를 복호화할 수 없습니다. API 응답에는 `hasPassword`만 있고, 공유 SQL에는 로그인 정보가 없습니다. 예전 버전이 브라우저에 저장한 프로젝트는 프로젝트 설정 화면을 처음 열 때 서버 저장소로 옮겨집니다. 검사 규칙과 아이디 기억은 아직 브라우저 저장소를 씁니다.

## 시작하기

Python 3.10 이상이 필요합니다. 개발 검증 환경과 고정 라이브러리는 `requirements.txt`와 구현 현황에 기록합니다.

Windows에서는 `setup_windows.bat`를 한 번 실행해 가상환경·의존성·Chromium을 설치한 다음, `run_windows.bat`를 실행하세요. 기본 주소는 **[http://127.0.0.1:3000](http://127.0.0.1:3000)**입니다. 서버는 loopback에만 바인딩합니다.

직접 실행하려면:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe app.py
```

macOS/Linux에서는 `.venv/bin/python`을 사용합니다. 포트 변경은 `PORT` 환경변수, 로컬 결과 폴더 변경은 `QA_RUNS_DIR` 환경변수로 가능합니다. WindowsApps Python 별칭만 있는 경우 실제 Python을 설치하세요. 제공 스크립트는 `.venv` 또는 설치된 Python 실행 파일을 찾습니다.

## 먼저 합성 데모 실행

1. 환경에서 **합성 데모**를 선택하고 담당자를 입력합니다.
2. 기본 설정으로 검사를 시작합니다. 앱 안의 A/B 데모에만 접속하며 외부 요청이 필요하지 않습니다.
3. 페이지/영역별 결과를 열어 매칭 근거, 검증식, 스크린샷, 발견·차단된 행동을 확인합니다.
4. 상태·차이율·비교 불가·영역·검색 필터로 범위를 좁히고 검수 사유를 저장합니다.
5. 실행 이력에서 다시 열거나 CSV/JSON을 내려받습니다. 앱 재시작 후에도 결과와 검수 이력이 남습니다.

데모에는 의도적으로 **B의 필수 Help 버튼 누락**, **서버별 공지 내용 차이**, **`.do` 경로 차이**, **절대 실행하면 안 되는 저장/삭제 함정**이 들어 있습니다. 따라서 모든 행이 PASS인 것이 데모의 정답이 아닙니다. `/demo/meta`는 합성 정답 라벨과 함정 실행 횟수를 제공합니다.

## 기능 검증의 4층 구조 — 무엇이 자동이고 무엇이 아직 아닌가

```
① 발견      DOM 스캔으로 링크·버튼·폼을 전부 목록화 (실행 아님)                         완성
② 정책      삭제·저장·결제·회원가입·POST 폼·다운로드 차단, 읽기 링크만 통과                 완성
③ 실행·계약  동작마다 기대값이 있어야 판정한다
   ③-a 페이지 계약   문서 응답 <400, 필수 영역 표시, 조건식(visible/count/text_length/overflow)  완성
   ③-b 스모크 계약   버튼 클릭 → 같은 출처 유지 · 새 JS 오류 없음 · 문서 응답 유지 (`smokeActions`)   완성
   ③-c 기능 시나리오 입력→결과 계약 (검색어 → N건, 탭 → 영역) `qa/scenarios.py`              엔진 완성 · 실사이트 계약 미등록
④ 증거·판정  스크린샷·HTTP·JS 로그 첨부 → 7상태 → 이슈/대인체크/재검 분류                   완성
```

설계 원칙은 **계약 없는 클릭에 PASS를 주지 않는다**입니다. ③-b는 "눌러도 깨지지 않는다"까지만 보장하는 스모크이고, 업무 기대값은 ③-c 시나리오로만 판정합니다. 현재 ③-c는 합성 데모용 3개(`demo.search`, `demo.input_length`, `demo.history`)만 있으며, 실사이트 시나리오 등록(JSON DSL)과 LLM 기반 시나리오 초안 제안이 다음 단계입니다.

**전체 기능 자동 체크 프리셋**(설정 화면 상단 ⚡ 버튼): 테스트 계정 자동 로그인(선택자 없이 로그인 링크→비밀번호 입력란 자동 탐지) → 환경 내부 읽기 링크 전체 탐색(60페이지·깊이 4·동작 400·40분; 한도는 최대 200페이지·깊이 8·동작 1000·1시간) → 발견한 버튼 스모크 클릭 → 사소한 시각 차이(8% 미만) PASS → 콘솔·리소스 오류는 "기타"로 분리(`observationMode: lenient`). 회원가입·계정·쓰기 경로는 ②에서 자동 제외됩니다.

## 네 가지 테스트 목적

| 목적 | 실제 실행 | 사용 시점 |
|---|---|---|
| 환경 비교 QA | A/B를 각각 검사하고 승인된 페이지·영역을 비교 | 운영↔STG, 개발1↔개발2 |
| 단일 환경 QA | A만 방문해 HTTP/JS·필수 영역·등록 시나리오를 검사 | 개발 서버 하나의 상태 확인 |
| 회귀 테스트 | 현재 A를 새로 검사하고 선택한 과거 실행과 비교 | 신규·반복·해결 후보·미재검 구분 |
| 조건 기반 UI QA | A의 현재 화면에서 조건·기대값 계약을 검사 | 긴 제목·빈 목록·페이지네이션 등 |

테스트 목적과 검사 모드(통합/시각/발견)는 별도로 저장합니다. 단일 환경·회귀·조건 기반 검사는 B 서버에 접속하지 않습니다. 회귀는 버전·범위·브라우저 조건이 맞는 실행끼리 평가하며, 누락되거나 차단된 검사를 해결로 취급하지 않습니다. 과거의 A/B 비교 실행을 단일 환경 실행과 동일한 범위로 간주하지 않습니다.

**같은 앱인데 `/`·`/#/`·`/main`·`.do`로 URL이 다른 경우:** 기본으로 켜진 ‘동등 라우트 매칭’이 `#/` 접두어·페이지 확장자·끝 슬래시·홈 별칭만 접어 같은 라우트로 대응시킵니다(`EQUIVALENT_ROUTE`). 제목이 같거나 `#/`만 다르면 확정하고, 아니면 후보로만 제안합니다. 상세 ID·쿼리가 다른 페이지는 접지 않으며 명시적 별칭이 우선합니다.

**시작 페이지가 커버·랜딩 화면으로 열리는 경우 (예: 레거시 모바일 `/#/` → `/#/coverPage` → ‘모바일 웹으로 이동하기’):** 설정 2단계의 ‘커버·랜딩 페이지 통과’에 버튼 선택자(필요하면 글자·URL 패턴·적용 환경)를 넣으면 시작 페이지에서 그 버튼이 보일 때 한 번만 누르고 이동한 화면을 시작 페이지로 삼습니다. 결과에는 `a.entry`/`b.entry` 검증식(`ENTRY_ACTION_APPLIED`, 전후 URL)이 남고, 버튼이 없으면 비필수 SKIP으로 지나갑니다. 다른 경로로 완전히 이동한다면 그 경로를 허용 경로에 추가해야 합니다. 대안으로 통과 후 URL을 직접 시작 URL로 입력해도 됩니다.

**같은 시작 페이지의 URL이 다른 경우:** 환경 비교에서 기본으로 선택된 ‘입력한 A/B 시작 URL을 같은 기능 페이지로 비교’를 사용합니다. 예를 들어 A `/#/`와 B `/`는 제목이나 최종 리다이렉트 경로가 달라도 입력한 두 시작 레코드끼리 한 행으로 연결합니다. 다른 탐색 페이지와 `#/notice`·`#/search`, 다른 상세 ID는 이 규칙으로 합치지 않습니다. 명시적 alias가 있으면 alias를 우선합니다. 실제 화면 준비·오류 관찰은 매칭과 별도로 판정합니다.

**차이율이 ‘미계산’인 경우:** ‘탐색만’ 모드는 URL·동작·오류를 발견하고 픽셀 비교를 하지 않습니다. 기존 실행의 ‘이 실행 설정으로 화면 비교 준비’에서 설정을 복원한 뒤 화면 검사로 새 실행을 시작하세요. 과거 보고서의 상태·모드는 바꾸지 않습니다.

조건 검사는 `visible`, `count`, `text_length`, `overflow`, `attribute`를 지원합니다. 화면이나 DB를 변경하거나 임의 JavaScript를 실행하지 않습니다. `long_title`, `empty`, `pagination` 사례는 데이터 전제조건이 필수이며 충족하지 못하면 BLOCKED입니다. 예시:

```json
[
  {
    "id": "notice.empty.message",
    "case": "empty",
    "url_pattern": "/notice*",
    "preconditions": [{"selector": ".notice-row", "kind": "count", "expected": {"equals": 0}}],
    "selector": "#empty-message",
    "kind": "visible",
    "expected": true
  }
]
```

위 선택자는 형식 예시입니다. 운영 DB에 데이터를 생성하지 않으며 조건에 맞는 URL·테스트 데이터를 먼저 준비해야 합니다. mock 응답 주입·DB 검증을 수행했다고 표시하지 않습니다.

## URL 구조가 다른 환경의 페이지 목록 만들기

제품과 환경을 분리합니다. 네 제품별 운영·STG·바이브 개발·레거시 개발 **16개 등록 주소** 중 A/B를 선택하면 URL이 채워집니다. 직접 입력과 환경 이름 변경도 가능합니다. `stg-`/`dev2-`/`-dev` 등을 일괄 제거하거나 다른 호스트를 추측하지 않습니다. [등록표](docs/ENVIRONMENT_URLS.md)에 제공 주소와 보존 규칙을 정리했습니다.

**탐색만 → 환경 내부 읽기 전용 링크 탐색 → 실행 → 환경별 페이지 목록·매칭 후보 검수 → 매핑 JSON에 추가 → 화면/통합 새 실행** 순서로 사용할 수 있습니다. 안전한 같은 출처 링크를 한도 안에서 탐색하고, 다른 URL이라도 메뉴 경로·폼·버튼·구조가 대응하면 REVIEW 후보로 연결합니다. 공통 템플릿만 같은 페이지나 서로 다른 상세 ID는 강제로 합치지 않습니다.

페이지 목록은 별도 CSV, 전체 근거는 JSON에 저장합니다. 후보를 추가해도 현재 보고서와 자동 상태를 바꾸지 않습니다. [환경 탐색·매핑 안내](docs/ENVIRONMENT_DISCOVERY.md)에 절차·범위·인터페이스를 정리했습니다.

등록 시나리오 `demo.search`, `demo.input_length`, `demo.history`는 검색(버튼/Enter/결과 없음), UTF-16 기준 10자 입력 경계, 목록→상세→뒤로가기·새로고침을 검증합니다. 이 기대값을 실제 회사 사이트의 요구사항으로 적용하지 않습니다.

## 실사이트 설정

네 제품에 운영·STG·바이브 개발·레거시 개발 주소를 모두 등록했습니다. 중고등 모바일 STG는 사용자 확인 주소 `https://stg-mv.vivasam.com/`입니다. 운영 모바일은 `/`, 레거시 모바일은 `/#/`로 구분하며, PC의 제공된 `/main`도 보존합니다. 주소 등록과 실제 사이트 접속·로그인·기능 검증은 별개이며 이번 개발 테스트는 합성 환경만 사용했습니다.

- 최초 URL과 명시적으로 매핑한 경로, 고급 설정의 허용 경로만 자동 방문합니다. 다른 링크는 발견 목록과 차단 사유에 남습니다.
- `#/...` route와 의미 있는 query 순서를 보존합니다. `.do`를 일괄 제거하지 않습니다. 구조 유사 후보는 REVIEW이며 승인 매핑으로 확정합니다.
- 허용 호스트는 정확한 `host[:port]`를 입력합니다. 외부 CDN/인증 호스트가 차단되면 결과의 `POLICY_BLOCKED`와 누락 범위를 확인한 후 필요한 호스트만 추가합니다.
- 정적 CDN은 별도 `resourceHosts`에 입력합니다. GET/HEAD의 script/stylesheet/image/font/media만 허용하며 해당 호스트로 이동하거나 로그인을 허용하지 않습니다. 네 제품 프로필에는 실제 실행에서 확인한 공용 자산 호스트(`www/stg/dn/dn22.vivasam.com`, Google Fonts, jQuery CDN, Kakao·Google 로그인 SDK)가 기본 등록되어 있고, 추적·광고 호스트(GTM, widerplanet, vsaidt, channel.io)는 포함하지 않습니다. 정적 자원 URL에는 delete/save 같은 단어 검사도 적용하지 않습니다(`ico_save.svg` 오탐 방지).
- 페이지가 로드 중 스스로 보내는 XHR/fetch는 허용 호스트에 한해 메서드와 무관하게 통과시킵니다(`xhrPolicy: allow_allowed_hosts`, 기본). 실제 사이트의 조회 API가 POST인 경우가 많아 이를 막으면 화면이 렌더링되지 않기 때문입니다. URL에 변경 단어(delete/save/submit…)가 있으면 여전히 차단하며, `block_writes`로 바꾸면 이전처럼 GET만 허용합니다. 사용자 클릭으로 발생하는 폼 제출·링크 이동 정책은 그대로입니다.
- 자동 POST/업무 변경/다운로드/알 수 없는 버튼은 기본 차단합니다. DOM 클릭 성공만으로 기능 정상 PASS를 만들지 않습니다.
- 현재 `safeActions`는 승인된 click 실행만 제공합니다. 행동의 정식 기대값 검사는 Python 시나리오로 확장해야 합니다.

고급 매핑 예시(실제 사이트 설정이 아닌 형식 예시):

```json
[
  {"baseline": "/old/notice.do", "candidate": "/new/notice", "page_class": "notice.list"}
]
```

영역 설정 예시:

```json
[
  {"id": "home.navigation", "selector": "#site-nav", "required": true, "mask_selectors": []},
  {"id": "home.notice", "selector": "#notice-list", "required": true, "mask_selectors": [".notice-title"]}
]
```

selector는 대상 화면에서 확인해야 합니다. 마스크가 데이터값 차이를 가려도 영역의 존재/가시성 검사는 수행합니다. 현재는 일반적인 텍스트 겹침·잘림을 전부 판정하는 엔진이 없으므로 마스크만으로 UI 정상이라고 결론내리지 않습니다.

## 로그인과 두 사람의 작업

**화면 구성:** 왼쪽 사이드바에서 **대시보드**(최근 실행의 이슈·대인체크·재검 요약, 실행 목록) · **프로젝트 설정**(환경 묶음·환경별 로그인 정보) · **검사 규칙**(조건 기반 UI 규칙을 만들어 검사 설정으로 전달) · **검사 실행·결과**로 이동하고, 아래 스위치로 라이트/다크/시스템 테마를 고릅니다.

**가장 빠른 사용법 — 전체 기능 자동 체크:** `setup_login_windows.bat`로 공용 계정을 한 번 저장 → 제품·A/B 선택 → **⚡ 전체 기능 자동 체크 프리셋** 클릭 → 검사 시작. 프리셋은 자동 로그인(선택자 자동 탐지), 환경 내부 읽기 링크 전체 탐색(60페이지·깊이 4·동작 400·40분; 한도는 최대 200페이지·깊이 8·동작 1000·1시간), 발견한 버튼 스모크 클릭, 시각 임계값 8%(사소한 차이 PASS), 관찰 오류 완화(콘솔·리소스 오류는 "기타"로 분리), 커버 페이지 통과를 한 번에 켭니다. 회원가입·계정·쓰기 경로는 정책상 자동 제외됩니다. 기능 FAIL은 페이지 자체 오류, 필수 영역 누락, 등록 시나리오 위반, 스모크 클릭 중 JS 오류·출처 이탈에서만 납니다.

**안전 수준 두 가지:** `strict`(기본) — 저장·삭제·등록·POST 폼·계정 경로를 모두 차단하는 읽기 전용. `test_account` — 테스트 계정으로 할 수 있는 쓰기 동작(게시·저장·삭제·폼 제출, 빈 입력란은 "QA자동테스트"로 채움)과 마이페이지·설정 경로까지 실행합니다. 프리셋이 이 수준을 켭니다. 어느 수준에서도 **회원탈퇴·비밀번호 관련·로그아웃·결제·회원가입**은 차단합니다 — 공용 테스트 계정이 망가지면 다음 실행부터 전부 로그인 실패가 되기 때문입니다. 운영에서 `test_account`를 쓰면 테스트 계정 명의의 데이터가 운영 DB에 생길 수 있으니 계정 권한이 테스트 범위를 넘지 않는지 확인하세요.

**계정이 전부 공용이면** 검사 화면 4단계 ‘로그인’에서 ID·비밀번호를 넣고 **계정 저장**을 누르거나, `setup_login_windows.bat`를 한 번 실행해 ID·비밀번호를 입력하면 `secrets/accounts.json`(git 제외)에 `default` 계정으로 저장되고 A/B 모든 환경·모든 프로필에 그 하나가 쓰입니다. **테스트 계정 자동 로그인**은 로그인 폼 선택자(아이디·비밀번호·버튼·성공/실패 표시)만 설정하고, 계정은 이 PC의 환경변수 `QA_LOGIN_A_ID`/`QA_LOGIN_A_PW`(B는 `_B_`) 또는 `secrets/accounts.json`에서 읽습니다. 보고서에는 `a.login` 검증식의 PASS/BLOCKED와 출처 종류만 남고, 계정 문자열은 JSON·CSV·캡처 어디에도 없습니다. 자격증명이 없으면 `LOGIN_CREDENTIALS_MISSING`으로 재검 분류됩니다. 자세한 절차와 보안 체크리스트는 [로그인·비밀 관리](docs/LOGIN_AND_SECRETS.md)를 보세요.

**수동 로그인**을 선택하면 실제 Chromium 창이 열립니다. 각 환경에서 사용자가 직접 로그인하고 앱에서 계속을 누릅니다. 비밀번호·세션 파일을 API나 디스크에 저장하지 않으며, 세션은 해당 실행의 환경별 context에만 유지됩니다. SSO·OTP처럼 자동 입력이 불가능한 경우에 사용합니다.

아이디 기억은 선택 기능입니다. 체크한 경우에만 현재 브라우저의 localStorage에 담당자/프로필/A·B별 ID를 저장합니다. 비밀번호 저장·자동 붙여넣기는 없습니다. 공용 PC에서는 사용하지 말고 지우기 기능으로 제거하세요.

두 사람은 담당자 이름으로 실행·검수를 구분합니다. 검수 저장은 revision으로 충돌을 검출하며 자동 판정은 덮어쓰지 않습니다. 사유와 기존 이슈의 http(s) URL을 검수 이력에 기록할 수 있습니다. 외부 이슈를 자동 생성하지 않습니다. **한 서버에서 동시 실행은 1개이며, 같은 결과 폴더의 중복 서버 실행도 차단**합니다. 담당자 문자열은 사용자 인증 기능이 아닙니다.

## 판정과 저장

| 상태 | 의미 |
|---|---|
| PASS | 실제 실행한 검증식의 기대값 충족 |
| FAIL | 명시한 기대값 위반 또는 현재 오류 정책의 실패 관찰 |
| DIFF | 승인된 매칭과 준비 조건에서 차이를 확인했지만 버그 여부 미확정 |
| REVIEW | 매칭·준비·기대값 등 판단 근거 부족 |
| SKIP | 설정·범위·안전 정책상 제외 |
| BLOCKED | 인증·데이터·선행 검사·실행 한도로 수행하지 못함 |
| ERROR | 브라우저·수집·비교·실행기 오류로 판정 불가 |

자동 판정 위에 **검수 분류**가 붙습니다: `ISSUE`(이슈 등록 후보) · `HUMAN_CHECK`(대인체크 — DB/이미지 차이, 매핑, 오류는 있지만 동작) · `RETEST`(재검 — 로그인·데이터·한도) · `OK` · `NOT_RUN`. 규칙은 [검수 분류 정책](docs/TRIAGE_POLICY.md)에 결정표로 있고, 보고서 `row.triage`·`totals.triage`, CSV의 `검수 분류`·`분류 사유` 열, UI 타일·배지·필터로 노출됩니다. 분류는 제안이며 자동 판정과 검수 이력을 바꾸지 않습니다.

**공지·게시판이 끝까지 다 열리는 문제:** 공지 상세·이전글/다음글·목록 페이지 번호처럼 번호만 다른 같은 화면은 ‘같은 모양 페이지 샘플 수’(기본 3)만큼만 방문하고 나머지는 "샘플링으로 생략" 한 줄(SKIP·미실행)로 묶습니다. 숫자 경로·`id/idx/no/seq` 계열 파라미터·숫자 값만 와일드카드로 보고, 경로와 그 밖의 파라미터가 다르면 다른 화면입니다.

**A·B가 따로따로 나오는 행이 많을 때:** 환경 비교에서 B는 A가 방문한 라우트를 먼저 그대로 방문하므로(짝 우선 탐색) 대부분 한 행으로 묶입니다. 그래도 한쪽만 있는 행은 실제로 그 환경에만 있는 페이지이거나 한도에 걸린 것이며, 미방문 페이지는 환경별 요약 행 하나로만 표시됩니다.

**비교샷이 "완전히 다르게" 나올 때 확인 순서:** ① B 쪽이 로딩 스피너·빈 영역이면 데이터 호출이나 정적 자원이 차단된 것입니다 — 결과의 `POLICY_BLOCKED` 목록에서 호스트를 보고 `resourceHosts`에 추가하세요(등록 프로필에는 `www/stg/dn.vivasam.com`, 폰트·카카오·구글 SDK가 기본 포함). 페이지가 스스로 보내는 POST 조회 API는 기본 정책(`xhrPolicy: allow_allowed_hosts`)에서 허용됩니다. ② 한쪽에만 마케팅 팝업·공지가 떠 있으면 기본 켜진 ‘팝업·공지 레이어 자동 닫기’가 닫기/오늘 하루 보지 않기 버튼을 눌러 닫습니다(기록 `OVERLAYS_DISMISSED`). 못 닫는 레이어는 3단계의 ‘캡처 전 닫을 팝업 선택자’에 닫기 버튼을 넣거나 `regions`로 비교 범위를 좁히세요. 또한 추적기 같은 외부 호스트 차단은 더 이상 비교 가능성을 깎지 않으며, 페이지 자체(동일 출처·허용 호스트)의 자원이 차단된 경우만 `readiness.renderingBlocked`로 기록하고 REVIEW로 둡니다 — 그래서 임계값(기본 8%) 아래의 사소한 차이는 PASS가 됩니다. ③ 시작 페이지가 커버 화면이면 ‘커버·랜딩 페이지 통과’를 쓰세요. 캡처 직전에는 두 환경 모두 **맨 위로 스크롤**(부드러운 스크롤 끔)하고, 로딩 스피너·스켈레톤이 사라지고 뷰포트 안 이미지가 다 로드되고 문서 높이·노드 수가 두 번 연속 같아질 때까지(기본 최대 4초, `captureSettleMs`) 기다립니다. 결과는 `readiness.settled`·`settleState`에 남고, 시간 안에 안정되지 않으면 비필수 `CAPTURE_NOT_SETTLED`가 기타에 기록됩니다. 그래도 흔들리는 영역(배너 롤링·동영상)은 `regions[].mask_selectors`나 팝업 닫기 선택자로 가리세요.

**실행 기록 삭제:** 실행 이력 패널의 🗑(완료된 기록 전체)와 각 항목의 ×로 보고서와 스크린샷 폴더를 영구 삭제합니다(`POST /api/scans/{id}/delete`, `POST /api/scans/delete-finished`). 진행 중인 실행은 삭제할 수 없습니다.

차이율 필터는 조회 범위만 바꿉니다. 0%와 비교 불가(null)를 구분하고, FAIL/ERROR는 별도 요약에도 남깁니다. 400/401/403은 일괄 무시하지 않으며 현재 정책은 출처·resource type을 구분합니다. endpoint별 예상 인증 응답 계약은 후속 작업입니다.

도구의 정책 차단 이후 발생한 JS·콘솔 오류는 `TEST_INFRA/POLICY_INTERFERENCE`로 구분하고 원시 메시지·관련 차단 요청과 함께 REVIEW로 표시합니다. 시간상 전후 관계만으로 정책이 원인이라고 확정하지 않습니다. 요청의 ERR_ABORTED도 실제 연결 장애로 단정하지 않으며 실행기가 닫으면서 취소한 요청만 별도 SKIP입니다.

발견 사항에는 HTTP/NETWORK/JAVASCRIPT/API/RESOURCE/NAVIGATION/STRUCTURE/FUNCTIONAL/VISUAL/DATA/AUTH/TEST_INFRA 분류를 적용합니다. 분류 사전의 존재가 모든 세부 항목의 자동 탐지를 의미하지 않습니다. 원시 관찰 수·결과 행 수·중복을 묶은 발견 사항 수·연결 이슈 수를 따로 표시하며, 같은 증거가 페이지와 영역에 함께 표시되어도 두 번 세지 않습니다. 고유 발견 사항도 검수 전에는 고유 제품 결함 수가 아닙니다.

`runs/<run-id>/report.json`에 실행 설정·결과·검수 이력, `a/`, `b/`, `diff/`에 PNG가 저장됩니다. 실행 중 앱이 종료되면 다음 시작 시 해당 run을 `PROCESS_INTERRUPTED` 오류로 표시합니다. 결과 폴더는 `.gitignore`에 포함됩니다. URL 인증 파라미터·일부 로그 문자열을 제거하지만 모든 개인정보를 자동 탐지하는 기능은 아니므로 실제 서비스 증거를 공개하기 전 검수해야 합니다.

신규 결과는 스키마 2.0입니다. 기존 1.x 결과는 원래 판정 그대로 열며 REVIEW/SKIP을 일괄 변환하지 않습니다. 저장 실패 시 실행을 ERROR로 표시하고 현재 서버의 메모리 결과를 JSON으로 내려받을 수 있게 유지합니다. 프로세스가 종료된 뒤 저장되지 않은 메모리 결과는 복구할 수 없습니다.
