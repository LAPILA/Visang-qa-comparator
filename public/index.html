환경 이름은 표시용이며 자유롭게 수정할 수 있습니다. 이름을 바꿔도 URL은 변경되지 않습니다.

시작 페이지 쌍은 경로나 제목이 달라도 대응시킵니다. 이후 발견한 다른 페이지는 별도 매칭 규칙으로 비교합니다. 서로 다른 기능의 시작 페이지라면 체크를 해제하세요.

같은 앱의 세대별 URL 차이를 자동으로 대응시킵니다. 제목이 같거나 #/ 접두어만 다를 때 확정하고, 그 외에는 후보로만 제안합니다. 상세 ID·쿼리가 다른 페이지는 접지 않습니다.

커버·랜딩 페이지 통과 · 시작 페이지에서 버튼 한 번 누르기

예: 레거시 모바일 /#/가 /#/coverPage로 열리고 ‘모바일 웹으로 이동하기’를 눌러야 홈이 나오는 경우. 시작 페이지에서 지정한 버튼이 보이면 한 번 클릭하고, 이동한 화면을 시작 페이지로 삼습니다. 버튼이 없으면 그냥 지나갑니다(SKIP · 비필수). 다른 경로로 완전히 이동하면 그 경로도 허용 경로에 있어야 합니다.

조건에 맞는 현재 화면을 읽어 검사합니다. 데이터·화면을 임의로 변경하지 않습니다. 기대값이 없으면 REVIEW, 사전 조건을 만족하지 못하면 BLOCKED로 기록합니다.

            3어디까지 검사할까요
            

              
              
              
              
              
              
              
            

            
같은 모양 페이지 샘플 수: 공지 상세·이전글/다음글·목록 2페이지처럼 번호만 다른 같은 화면은 이 개수만 방문하고 나머지는 "샘플링으로 생략"(미실행)으로 묶습니다. 0이면 전부 방문. 한도: 페이지 최대 200 · 깊이 8 · 동작 1000 · 시간 3600초(1시간). 환경 비교는 동작 수를 A/B가 반씩 씁니다. 임계값은 이번 실행의 시각 차이 판정에 적용됩니다. 결과를 좁히는 차이율 필터는 검사 후 별도로 사용할 수 있습니다.

            
            

            
확대 탐색은 선택한 각 시작 URL의 출처(scheme·host·port) 내부 읽기 링크에 한합니다. 다른 환경·외부 호스트, 계정·개인정보·쓰기 동작, POST, 다운로드와 API·데이터 파일은 제외합니다.

            

              
              
              
            

            
            
⚠ 테스트 계정 수준에서는 이 계정으로 할 수 있는 쓰기 동작을 실제로 실행합니다(게시·저장·삭제·폼 제출, 빈 입력란은 "QA자동테스트"로 채움). 운영 DB에 테스트 계정 명의의 데이터가 생길 수 있으니 계정 권한이 테스트 범위를 넘지 않는지 확인하세요. 회원탈퇴·비밀번호 변경·로그아웃·결제·회원가입은 공용 계정을 망가뜨리므로 이 수준에서도 차단됩니다.

            
            
            
마케팅 팝업은 환경·날짜마다 달라 차이율을 크게 올립니다. 닫기 버튼 선택자를 넣으면 캡처 전에 한 번 닫고 기록합니다. 데이터 호출 정책 기본값은 페이지가 스스로 보내는 조회 API(POST 포함)를 허용해 실제 화면이 렌더링되게 합니다. URL에 delete·save·submit 같은 변경 단어가 있으면 여전히 차단합니다.

              로그인 · 테스트 계정 / 수동 로그인 / 아이디 기억
              

                

                  
                  

                    
확인 중공용 테스트 계정 상태를 불러오는 중입니다.

                    

                      
                      
                      
                      
                    

                    
저장하면 이 PC의 secrets/accounts.json(git 제외)에만 기록되고 화면·검사 요청·보고서에는 남지 않습니다. 한 번 저장하면 모든 환경(A/B)·제품에 이 계정으로 자동 로그인합니다.

                  

                  

                    

                      
                      
                    

                    

                      
                      
                      
                    

                    

                      
                      
                    

                    

                      자격증명 제공 방법 (서버·보고서·화면에 절대 저장되지 않음)
                      
set QA_LOGIN_A_ID=테스트계정   set QA_LOGIN_A_PW=비밀번호     ← A 환경 (B는 QA_LOGIN_B_*)
또는 secrets/accounts.json: {"accounts": {"default": {"id": "...", "pw": "..."}, "default.b": {...}}}

                      환경변수 우선 → 공용 QA_LOGIN_ID/PW → 비밀 파일 순으로 찾습니다. 없으면 검사는 LOGIN_CREDENTIALS_MISSING(BLOCKED · 재검)으로 기록하고 추측하지 않습니다. 아이디 입력란은 캡처에서 자동 마스킹됩니다. secrets/는 .gitignore에 포함됩니다.
                    

                  

                

                

                  
                  
로그인 창에 아이디·비밀번호를 직접 입력한 뒤 이 화면에서 ‘로그인 완료 · 계속’을 누릅니다. 이 도구는 비밀번호를 입력받거나 저장하지 않습니다.

                

                
                

                  
                  
                

                
담당자·프로필·환경별로 이 PC의 브라우저에만 저장합니다. 체크를 해제하면 현재 담당자·프로필의 저장된 아이디를 지웁니다.

              

            


            

              고급 설정 · 페이지 매핑, 영역, 허용 동작
              

                
기본 탐색은 시작 페이지와 명시한 별칭·승인 경로만 허용합니다. 전체 허용(*)이나 목적이 불명확한 동작을 허용하지 않습니다. 정적 CDN과 탐색·API·인증 호스트는 용도에 맞게 나누어 등록합니다.

                
                
                
필요한 정확한 호스트를 한 줄에 하나씩 입력합니다. 호스트 등록만으로 모든 경로·동작을 허용하지는 않습니다.

                
                
스크립트·스타일·이미지·폰트 등 정적 자원 요청에만 쓰는 정확한 호스트입니다. 페이지 이동·API 호출·로그인 호스트를 허용하지 않습니다.

                
                
                
                
화면의 이름·계정 헤더 등 가릴 요소의 선택자를 문자열 배열로 입력합니다(최대 30개). 비밀번호 입력 마스킹은 기본 유지됩니다. 개인정보를 자동으로 찾아주는 기능은 아니므로 캡처 전 대상을 확인하세요.
